# Надёжность и безопасность данных

## Надёжность сообщений

- Входящее сообщение и Inbox job фиксируются одной транзакцией.
- Повторные события дедуплицируются по идентификатору платформы.
- Workers используют ограниченные повторы и восстановление зависших задач.
- Ответ и Outbox job также создаются атомарно.
- Каналы доставляются независимо и учитывают разные возможности идемпотентности.
- Ошибочные задачи остаются видимыми для диагностики и ручного retry.

Exactly-once delivery не заявляется: внешние API не дают такой гарантии для всех каналов. Вместо этого область возможного дубля локализована и явно учтена в channel-specific policy.

## Контроль AI-нагрузки

Персональные и общие дневные квоты ограничивают нагрузку на AI-провайдеров и остаются наблюдаемыми для администратора.

## Защита пользовательского текста

Исходные сообщения хранятся локально для истории и Manual Support. Перед внешним NLU или LLM локальный Privacy Gateway создаёт очищенную версию текста.

Используются Unicode-нормализация, детерминированные распознаватели структурированных идентификаторов и Natasha NER. Ошибка Privacy Gateway блокирует внешний вызов; fallback на исходный текст отсутствует.

![Локальная проверка и маскирование персональных данных](<../images/Максировка персональных данных.png>)

_Проверочный экран демонстрирует результат локальной очистки до обращения к внешним NLU/LLM._

## Доступ и аудит

- Access token хранится в памяти вкладки.
- Refresh token находится в HttpOnly cookie и связан с серверной сессией.
- Login и refresh защищены rate limit.
- Чувствительные операции проверяют роль.
- Значимые изменения записываются в audit trail вместе с бизнес-транзакцией.
- Error tracking не получает сообщения, prompts, cookies, credentials и user IDs.

Техническое маскирование снижает риск передачи персональных данных, но не заменяет согласия, retention policy, договоры и организационную матрицу доступа.

_Audit trail связывает действие, исполнителя, источник и объект изменения._

## Наблюдаемость

Liveness, readiness и health разделены. Мониторинг отслеживает состояние каналов, Inbox/Outbox, AI-контекста, event extraction и резервных копий. Повторяющиеся ошибки группируются, чтобы не создавать поток одинаковых инцидентов.
